3 Frontend in PocketBase ablegen

Aktuelles Modell (seit 02.07.2026): Die drei .dc.html-Dateien (Design Components) werden direkt — nicht als Standalone-Export — als index.html/buchung.html/start.html nach pb_public/ kopiert. Eine gemeinsame support.js wird zusätzlich nach pb_public/support.js deployt und von allen drei Seiten per absolutem Pfad (/support.js) eingebunden. Kein Standalone-Export mehr nötig.

QuelldateiZiel in pb_publicURL
Kühlwagen-Verwaltung.dc.htmlindex.html/index.html
Buchungsanfrage.dc.htmlbuchung.html/buchung.html
Startseite.dc.htmlstart.html/start.html
support.jssupport.js/support.js
1
Deploy-Script ausführen 
# Im Repo-Ordner (C:\Projekte\kuehlwagen):
.\deploy.bat
Führt deploy.ps1 aus: sucht die drei .dc.html-Dateien + support.js im Repo, lädt sie per SCP hoch und kopiert sie per docker cp in pb_public/. Kein Container-Neustart nötig (reines Frontend).
Voraussetzung: SSH-Zugang funktioniert (setup-ssh-key.ps1 einmalig ausführen, dann kein Passwort mehr nötig). support.js Pfad im HTML muss absolut sein (/support.js), sonst falscher Pfad je nach URL.
2
Fertig! App aufrufen: https://kw.hofreither.at/start.html (Einstieg) → index.html (Verwaltung, Login) oder buchung.html (öffentliche Anfrage).

4 Updates einspielen

Wenn du eine neue Version einer der drei Seiten hast (per VS Code oder Claude Design Editor bearbeitet):

  1. Geänderte .dc.html im Repo-Ordner ablegen (falls über Claude bearbeitet: Datei herunterladen und im Ordner ersetzen)
  2. .\deploy.bat ausführen
  3. Fertig — die App zeigt die neue Version beim nächsten Browser-Reload
Nur bei Änderungen an pb_hooks/kw_anfragen.pb.js: stattdessen .\deploy-hooks.bat verwenden — deployed zusätzlich den Hook und startet den Container neu (nötig, damit PocketBase den Hook neu lädt).

5 Datensicherung

Manuelles Backup

Das gesamte Datenvolume (/pb_data) enthält die SQLite-Datenbank. Einfach kopieren:

docker cp <container-id>:/pb_data ./backup-$(date +%Y%m%d)

App-internes Backup

Nutzerinnen können jederzeit über Stammdaten → Backup exportieren eine JSON-Datei herunterladen und lokal aufbewahren.

7 E-Mail-Benachrichtigungen einrichten

SMTP-Anbieter: Brevo

Brevo ist kostenlos (300 Mails/Tag), braucht keine Server-Installation — nur Zugangsdaten konfigurieren.

1
Account erstellen
Kostenlos registrieren auf brevo.com → E-Mail-Adresse bestätigen
2
SMTP-Zugangsdaten holen
Brevo Dashboard → SMTP & API → Tab SMTP → Daten notieren:
Host, Port (587), Login, Passwort
3
In PocketBase konfigurieren
kw.hofreither.at/_/ → Settings → Mail settings:
FeldWert
SMTP Hostsmtp-relay.brevo.com
SMTP Port587
UsernameDeine Brevo-E-Mail
PasswordBrevo SMTP-Passwort
Sender Addressrathaus@st-valentin.at
Sender NameKühlwagen-Verleih St. Valentin
4
Hook-Datei in den Container kopieren 
# Datei pb_hooks/kw_anfragen.pb.js auf Server hochladen, dann:
docker exec <container-id> mkdir -p /pb_data/pb_hooks
docker cp kw_anfragen.pb.js <container-id>:/pb_data/pb_hooks/kw_anfragen.pb.js

# Container neu starten damit Hooks geladen werden:
docker restart <container-id>
Die Hook-Datei liegt im Projekt unter pb_hooks/kw_anfragen.pb.js. Sie versendet drei Arten von Mails: neue Anfrage (an alle Mitarbeiterinnen), Genehmigung/Ablehnung (an Anfragende), Buchungsbestätigung (an Kundschaft, ausgelöst über kw_state).
Wichtig: Die Buchungsbestätigung merkt sich per _mailSent-Flag im Buchungsdatensatz, ob schon verschickt wurde, um bei den häufigen Autosaves (alle 300ms) keine Dubletten zu verschicken. Nach jeder Änderung an dieser Logik unbedingt mit einem Testfall ohne echten SMTP-Versand prüfen, dass keine Endlosschleife aus Save-Aufrufen entsteht.

8 Root-Redirect (/ → /start.html)

Standardmäßig liefert PocketBase unter / direkt die Verwaltungs-App (index.html) aus. Damit Besucher stattdessen zuerst die Startseite mit den zwei Buttons sehen, wird in Coolify eine Traefik-Middleware ergänzt.

1
Router-Namen ermitteln In Coolify: Projekt kuehlwagen → Environment production → Ressource (Application-ID meist als docker-image-<uuid> benannt) → Tab mit den generierten Labels. Dort den Namen des HTTPS-Routers notieren, z.B.: 
traefik.http.routers.https-0-<uuid>.middlewares=gzip
2
Middleware ergänzen und Router-Zeile ersetzen (nicht doppelt anlegen — die alte ...middlewares=gzip-Zeile muss ersetzt, nicht ergänzt werden): 
traefik.http.middlewares.kw-root-redirect.redirectregex.regex=^https://kw\.hofreither\.at/$
traefik.http.middlewares.kw-root-redirect.redirectregex.replacement=https://kw.hofreither.at/start.html
traefik.http.middlewares.kw-root-redirect.redirectregex.permanent=true
traefik.http.routers.https-0-<uuid>.middlewares=gzip,kw-root-redirect
3
Speichern, redeployen, testen 
curl.exe -I https://kw.hofreither.at/
# Erwartet: 308 Permanent Redirect → Location: https://kw.hofreither.at/start.html
# Andere Pfade (/index.html, /buchung.html) bleiben unberührt, da der Regex mit $ nur die exakte Root-URL matcht.
Der ^...$-Anker im Regex ist entscheidend — ohne ihn würde die Middleware auch /index.html & Co. treffen und die App unerreichbar machen.

Frontend-Änderung deployen

Aktuelles Modell: .dc.html-Dateien + support.js direkt (kein Standalone-Export), siehe Schritt 3.

# Im Repo-Ordner:
.\deploy.bat

Hook-Änderung (pb_hooks/kw_anfragen.pb.js) deployen

# Im Repo-Ordner — deployed Frontend + Hook, startet Container neu:
.\deploy-hooks.bat

Manuell (falls die Scripts nicht verfügbar sind) — in alle drei Kandidaten-Pfade kopieren, da der aktive hooksDir-Pfad variieren kann:

scp "pb_hooks\kw_anfragen.pb.js" root@116.203.141.156:/root/kw_anfragen.pb.js

# dann via SSH:
CONTAINER=$(docker ps --format '{{.ID}} {{.Image}}' | grep pocketbase | awk '{print $1}' | head -1)
docker exec $CONTAINER mkdir -p /pb_data/pb_hooks /pb_hooks /pb/pb_hooks
docker cp /root/kw_anfragen.pb.js $CONTAINER:/pb_data/pb_hooks/kw_anfragen.pb.js
docker cp /root/kw_anfragen.pb.js $CONTAINER:/pb_hooks/kw_anfragen.pb.js
docker cp /root/kw_anfragen.pb.js $CONTAINER:/pb/pb_hooks/kw_anfragen.pb.js
docker restart $CONTAINER   # nötig, damit der Hook geladen wird
PowerShell-Quoting-Falle: In einem ssh ... "..."-Aufruf aus PowerShell muss $ mit Backtick escaped werden (`$CONTAINER), nicht mit Backslash (\$CONTAINER) — PowerShell kennt keine Backslash-Escapes und würde den Befehl sonst kaputt interpolieren, bevor er überhaupt bei SSH ankommt.

Troubleshooting: SSH "Permission denied"

Falls SSH trotz korrektem Passwort scheitert, kann fail2ban die eigene IP nach ein paar Fehlversuchen gesperrt haben. Nur über die Hetzner VNC Console behebbar:

fail2ban-client status sshd        # gesperrte IPs anzeigen
fail2ban-client set sshd unbanip <IP>

10 Lokale Entwicklungsumgebung

Läuft komplett unabhängig vom Produktivserver, direkt im Projektordner. pocketbase.exe, pb_data/ und pb_public/ sind gitignored (nur lokal, nicht versioniert).

1
pocketbase.exe besorgen Von pocketbase.io/docs herunterladen, ins Projektverzeichnis legen.
2
Server starten 
./pocketbase.exe serve --http=127.0.0.1:8090
Kein Autostart eingerichtet — nach jedem Neustart manuell erneut ausführen.
3
Superuser + Collections einrichten Analog zu Schritt 2 und 6, aber lokal: http://127.0.0.1:8090/_/ aufrufen, Superuser anlegen, kw_state/kw_calendar/kw_booking_requests anlegen (PocketBase erzeugt dabei automatisch Migrationsdateien in pb_migrations/ — die sind versioniert und sollten committet werden).
4
Frontend-Dateien nach pb_public/ kopieren (gleiches DC+support.js-Modell wie Produktion, siehe Schritt 3): 
cp "Kühlwagen-Verwaltung.dc.html" pb_public/index.html
cp "Buchungsanfrage.dc.html"      pb_public/buchung.html
cp "Startseite.dc.html"           pb_public/start.html
cp "support.js"                   pb_public/support.js
Die App erkennt die PocketBase-URL automatisch über window.location.origin — kein manuelles Umschalten von PB_URL nötig, solange sie aus demselben pb_public-Ordner ausgeliefert wird.
URLs lokal: Startseite http://127.0.0.1:8090/start.html · Verwaltung http://127.0.0.1:8090/index.html · Buchung http://127.0.0.1:8090/buchung.html · Admin http://127.0.0.1:8090/_/
SMTP nicht konfiguriert: Die E-Mail-Hooks laufen lokal, aber ohne SMTP-Konfiguration in der lokalen PB-Admin-UI wird keine echte Mail verschickt (Fehler failed to locate a sendmail executable path im Log — das ist erwartetes Verhalten, kein Bug).
Windows-Besonderheit: --hooksWatch (Auto-Reload bei Hook-Änderungen) hat auf Windows keine Wirkung — nach jeder Änderung an pb_hooks/kw_anfragen.pb.js muss der lokale Server manuell neu gestartet werden.
Hinweis Gleichzeitiger Zugriff: Wenn mehrere Mitarbeiterinnen gleichzeitig Buchungen anlegen und kurz danach speichern, gewinnt die letzte Speicherung. Im Alltag mit wenigen Personen ist das kein Problem — für echte Echtzeitsynchronisation könnte man PocketBase-Subscriptions ergänzen.
